
# miniC Compiler

---
This project implements a compiler pipeline for a miniC program.

The compiler reads the miniC program and produces executable **x86-32 assembly** through several stages.

Pipeline:

1. Parse the input program using **Flex/Bison** and build an AST
2. Perform **semantic analysis**
3. Perform **variable renaming** so every variable has a unique name
4. Build **LLVM IR** (`output.ll`)
5. Run **register allocation** using a linear-scan algorithm
6. Generate **x86-32 assembly** (`output.s`)
7. Run an optional **optimizer** (reads `output.ll`, writes `output_opt.ll`)

The tests in the different folders follow the restricted **miniC grammar** used in this project.

---

# Requirements

The project requires the following tools:

- `clang++`
- `flex`
- `bison`
- `llvm-config-17`
- `gcc` (for linking generated assembly)

---

# Build

Build the compiler and optimizer:

```bash
make compiler
make optimizer
````

Or build everything:

```bash
make
```

During the build process, **Flex and Bison generate the lexer and parser files**.

the generated files include:

```
lex.yy.c        
parser.tab.c    
parser.tab.h 
```

These files implement the lexer and parser used by the compiler.

---

# Running the Compiler

You can run the compiler directly on a miniC file.

Example:

```bash
./compiler <input_file>
```

Example:

```bash
./compiler llvm_builder/builder_tests/p1.c
```

Outputs generated:

```
output.ll   # LLVM IR generated by the IR builder
output.s    # x86-32 assembly generated after register allocation
```

---

# Running the Optimizer

After `output.ll` is generated you can run the optimizer:

```bash
./optimizer output.ll
```

Output:

```
output_opt.ll
```

# Running and Comparing Builder Tests

The folder:

```
llvm_builder/builder_tests/
```

contains reference programs (`p1.c`, `p2.c`, etc.) used to test the IR builder.

### Step 1 — Compile with normal C compiler

```bash
clang llvm_builder/builder_tests/p1.c -o ref
./ref > ref.txt
```

### Step 2 — Compile with my compiler

```bash
./compiler llvm_builder/builder_tests/p1.c
clang output.ll run.c -o mine
./mine > mine.txt
```

### Step 3 — Compare outputs

```bash
diff ref.txt mine.txt
```

If `diff` prints nothing, the outputs match.

# Testing the Assembly Backend

The folder:

```
compiler_backend/assembly_gen_tests/
```

contains programs used to test the **full compiler pipeline**, including register allocation and assembly generation.

Example tests:

```
max_n.c
fact.c
```

These programs are compiled by the compiler and then linked with:

* `run.c` (runtime functions `read()` and `print()`)
* `main.c` (test driver that calls `func()`)

---

# Running an example Test(max_n)

### Step 1 — Generate assembly

```bash
./compiler compiler_backend/assembly_gen_tests/max_n.c
```

This produces:

```
output.ll
output.s
```

### Step 2 — Build executable

```bash
gcc -m32 output.s compiler_backend/assembly_gen_tests/main.c run.c -o max_n
```

### Step 3 — Run

```bash
./max_n
```

Example output:

```
5
9
4
2
In main printing return value of test: 9
```

# Some Notes

1. The file `run.c` provides functions used by generated programs:

2. the file `main.cpp` is the main file that runs all the compiler stages
